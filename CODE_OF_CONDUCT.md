# Code of Conduct — Kali-Lite

## Notre engagement

Kali-Lite est un projet open source porté par Kalicorp.

Nous souhaitons maintenir un environnement de contribution ouvert, professionnel et accueillant, dans lequel chacun peut participer sans harcèlement ni discrimination.

Les échanges doivent rester centrés sur :

- les faits ;
- le code ;
- les tests ;
- les usages ;
- les risques ;
- les compromis techniques.

Les désaccords sont normaux dans un projet technique.

Ils ne justifient ni les attaques personnelles, ni le harcèlement, ni l'intimidation.

---

## Nos standards

### Comportements encouragés

Nous encourageons notamment :

- l'entraide technique ;
- le partage de connaissances ;
- le mentorat ;
- les critiques constructives ;
- la vérification par les faits et les tests ;
- la reconnaissance de ses erreurs ;
- la documentation des limites d'une solution ;
- le respect des différents niveaux d'expérience ;
- le respect des différences de perspective et de contexte ;
- la recherche de solutions simples et reproductibles ;
- la contribution à une IA locale, inspectable et maîtrisable par son opérateur.

Une critique technique peut être directe.

Elle doit cependant porter sur :

```text
le code
le comportement
l'architecture
la documentation
les résultats
```

et non sur la personne qui contribue.

---

## Comportements inacceptables

Ne sont pas acceptés dans les espaces du projet :

- le harcèlement public ou privé ;
- l'intimidation ;
- les menaces ;
- les insultes ou attaques personnelles ;
- les propos discriminatoires ;
- le langage ou les images à caractère sexuel inapproprié ;
- l'attention sexuelle non sollicitée ;
- la publication d'informations privées concernant une autre personne sans son autorisation ;
- la divulgation volontaire de secrets, credentials ou données personnelles ;
- le trollage répété visant uniquement à perturber les échanges ;
- l'usurpation d'identité ;
- la manipulation volontaire de tests ou de résultats présentés ;
- la présentation volontaire d'une action comme exécutée alors qu'elle ne l'a pas été ;
- la tentative de contourner les règles de sécurité ou les permissions du projet ;
- l'utilisation des espaces du projet pour organiser ou faciliter des attaques non autorisées contre des systèmes tiers.

---

## Cybersécurité et recherche

Kali-Lite peut être utilisé dans des contextes de :

- diagnostic ;
- audit ;
- durcissement ;
- analyse de vulnérabilités ;
- investigation ;
- formation ;
- recherche en cybersécurité.

Ces sujets sont légitimes lorsqu'ils concernent :

- des systèmes appartenant au contributeur ;
- des environnements de laboratoire ;
- des CTF ou plateformes prévues à cet effet ;
- des systèmes pour lesquels une autorisation explicite existe.

Discuter d'une vulnérabilité ou d'une technique offensive n'est pas, en soi, une violation de ce Code of Conduct.

Ce qui n'est pas accepté est l'utilisation du projet ou de ses espaces pour faciliter une compromission réelle **sans autorisation**.

---

## Respect des données et de la vie privée

Ne publiez pas dans :

- une Issue ;
- une Pull Request ;
- un commentaire ;
- un log ;
- une capture d'écran ;

des informations sensibles qui ne sont pas nécessaires à la résolution du problème.

Cela inclut notamment :

- mots de passe ;
- clés API ;
- tokens ;
- cookies de session ;
- adresses privées ;
- informations personnelles ;
- données de clients ou d'organisations.

Lorsqu'un log contient ce type d'information, anonymisez-le avant publication.

---

## Responsabilités des mainteneurs

Les mainteneurs sont responsables de l'interprétation et de l'application de ce Code of Conduct dans les espaces du projet.

Ils peuvent notamment :

- demander une modification d'un message ;
- masquer ou supprimer un contenu ;
- fermer une Issue ou une Pull Request ;
- limiter temporairement une participation ;
- exclure un participant des espaces communautaires du projet.

Les décisions doivent, autant que possible, être :

- proportionnées ;
- documentées ;
- cohérentes ;
- fondées sur le comportement observé.

---

## Portée

Ce Code of Conduct s'applique aux espaces directement liés au projet Kali-Lite, notamment :

- Issues GitHub ;
- Pull Requests ;
- commentaires et reviews ;
- discussions du dépôt ;
- autres espaces communautaires officiels du projet.

Il s'applique également lorsqu'une personne représente explicitement Kali-Lite ou Kalicorp dans le cadre du projet.

Il ne vise pas à régir les opinions personnelles exprimées en dehors des espaces du projet lorsqu'elles sont sans rapport avec celui-ci.

---

## Signaler un incident

Un comportement problématique peut être signalé de manière privée à :

```text
kalicorp@proton.me
```

Merci d'indiquer, lorsque cela est possible :

- l'espace concerné ;
- les messages ou événements en cause ;
- les liens utiles ;
- la date approximative ;
- tout élément permettant de comprendre la situation.

Évitez de publier publiquement des informations personnelles supplémentaires pour documenter l'incident.

Les signalements seront examinés avec discrétion dans la mesure du possible.

---

## Vulnérabilités de sécurité

Le Code of Conduct n'est pas le canal destiné aux vulnérabilités techniques.

Pour signaler une vulnérabilité du projet, consultez :

[`SECURITY.md`](SECURITY.md)

Les vulnérabilités sensibles ne doivent pas être publiées dans une Issue publique.

---

## Principe général

Kali-Lite repose notamment sur une idée simple :

> **preuve avant affirmation, respect avant ego.**

On peut contester une architecture, démontrer qu'un choix est mauvais, casser un test ou proposer une autre approche.

On ne transforme pas pour autant le désaccord technique en conflit personnel.
